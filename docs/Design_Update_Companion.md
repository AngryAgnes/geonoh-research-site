# Design Update Companion

When proposing design changes, document the following:

- What changed: short summary of changes
- Why it changed: motivation and user benefit
- Affected tickets: list of tickets that must be reopened or updated
- Affected files: list of files to update
- Risks: migration and backward-compatibility issues
- Database/schema changes needed: yes/no and migration plan

Provide this companion with every PR that changes design or schema.
